# PACRE-VC v23 verifier preregistration

Frozen before the v23 generated-only receipts and before the new \(D_R\)
gate. The candidate is explicitly adaptive to the sealed v22 aggregate
\(D_R\) failure and is not an independent confirmation.

## Immutable model boundary

- Candidate: `PACRE-VC-v23`.
- The numerical forward, parameters, field, PMOPE objective, inputs
  \((F_b,O)\), hard union, and zero threshold are inherited unchanged from
  PACRE-v22.
- The v23 model and config have independent FQCNs and an exact-type factory.
- `forward_fields` must return exactly
  `cure_lite_v22.pacre.CoverageStatePACREFields`.
- CPU/CUDA raw-field, gradient, and three-step Adam parity must pass for
  generated seeds 42, 43, and 44.

## Algebra decision contract

The verifier has 15 forward-expression subchecks.

- Thirteen non-transcendental paths require same-device raw equality
  (`bound = 0`).
- Re-executing SiLU is not assumed raw-bit stable across tensor layouts and
  vectorized kernels. The two hidden paths use the frozen conservative bound

  \[
  B_H=4\epsilon_{32}
  \left(1+|\operatorname{SiLU}(J_s)|
  +|\operatorname{SiLU}(J_c)|\right)+\mathrm{TINY}_{32}.
  \]

- Phase reconstruction and phase centering use the FTZ-safe analytic bounds
  implemented in `cure_lite_v23/algebra_verifier.py`.
- `flip_delta` and flipped occupancy are explicitly replayed.
- The original v22 six-subcheck formulas and tolerances are replayed in full,
  but their observed PASS/FAIL outcomes have decision weight zero.
- FP64 oracle integrity is gate-eligible; oracle error magnitude and all
  signal-swallow counts are diagnostic-only.
- A CPU-FP32 `linspace(0.5, 1.5, width)` readout provides a nonzero functional
  diagnostic independently of the initialized zero scalar readout.
- Injecting `1e-3` into a stored residual, hidden, or energy field must fail
  its corresponding replay/bound.

## Generated-only matrix

- Formal shape: batch 1, channels 64, stride 4, hidden width 32, feature grid
  \(64\times64\), occupancy grid \(256\times256\), FP32.
- Seeds: 42, 43, 44.
- Devices: CPU and the v22-selected logical `cuda:0`.
- Inputs are generated by an independent CPU `torch.Generator`, fingerprinted,
  and only then copied to the selected device.
- Python, PyTorch, CUDA, cuDNN, GPU identity, deterministic switches, TF32,
  matmul precision, thread counts, numerical environment variables, and
  subnormal probes are frozen before generated input construction.

## Real-\(D_R\) gate

The sole run ID is
`pacre_v23_verifier_corrected_D_R_structural_r1`.

- Check 05 covers the 32 target-state forward calls.
- Check 13 separately covers the 96 context-state forward calls.
- Scope-qualified ledger IDs make all 128 forward-call records unique while

- The gate is read-only: no optimizer, no parameter update, no training.

## Formal-800 training contract

The final training budget is fixed before either the v23 generated-only
receipts or the new real-\(D_R\) run:

- run ID:
  `cure_lite_pacre_v23_vc_pmope_formal_800_seed42_r1`;
- seed: 42;
- initialization: from scratch, with no v21/v22/v23 checkpoint reuse;
- budget: exactly 800 epochs, 40 steps per epoch, and 32,000 optimizer
  updates;
- optimizer and objective: the inherited Adam/PMOPE training contract;
- data: the complete frozen \(D_R\) training scalar cache and the frozen
  Formal-800 exposure schedule;
- candidate: the exact v23 PACRE-VC config and factory;
- checkpoint policy: one final model checkpoint; no threshold search,
  intermediate-checkpoint selection, retry, resume, or overwrite;
- the final-model artifact embeds and validates the exact PMOPE objective,
  formal cache/schedule, `cuda:0`, seed/initial state, fresh-Adam policy,
  800-row ledger fingerprint, 32,001 finite-state audits, and final state;
- bounded-400 is neither a prerequisite nor final evidence and is not run in
  this attempt.

A terminal \(D_R\) 13/13 PASS is necessary but does not itself execute or
claim success for Formal-800.  The official Formal-800 runner must rebuild and
consume a unique process-local authorization bound to the terminal \(D_R\)
receipt, the dataset-free receipt, runtime lock, full real-input cache,
schedule, initial model, and live source closure.

Training completion is not a performance claim.  Formal-800 must not read
\(D_V\) or \(D_T\) tensor payloads.

## Relative performance contract

There is no arbitrary fixed uplift margin such as “at least \(+2\) targets.”
If a later, separately authorized evaluation is run, performance is judged
relative to the frozen best Base result:

1. `true_targets` must be strictly greater than the best Base value;
2. `recovered_anchor_misses` must be strictly greater than the best Base
   value;
3. mIoU and nIoU must not regress below their respective best Base values;
4. retention must remain 1.0 and the frozen false-alarm safety budgets must
   remain satisfied.

Thus a reproducible \(+1\) gain qualifies; no larger absolute effect size is
invented after observing results.  Items 3--4 prevent a nominal target-count
gain obtained by degrading the detector or flooding the background.

The following are not fixed performance-uplift margins:

- the zero level set is the immutable PACRE decoding rule;
- numerical equality/error bounds are verifier-correctness contracts;
- false-alarm and retention limits are operating-safety constraints.

No checkpoint, threshold, post-processing rule, metric, comparator, or safety
budget may be selected after revealing evaluation results.  Project-level
\(D_V\) was already revealed by v21, so any v23 \(D_V\) evaluation is adaptive
evidence.  \(D_T\) remains the later one-time confirmatory split.

## Stage discipline

1. Freeze all package and official runner sources.
2. Freeze CPU/CUDA runtime receipts and implementation closure.
3. Run parity, scalar counterexamples, CPU/CUDA formal stress, and the
   generated-only 22-check gate.
4. Create `D_R_pre_run_authorization.json` last.
5. Run exactly one read-only \(D_R\) gate.
6. Only a terminal 13/13 PASS may create and consume the unique seed-42
   Formal-800 authorization.
7. Run exactly one from-scratch Formal-800 attempt (800 by 40); do not run
   bounded-400.
8. Independently verify the append-only terminal Formal-800 artifact graph.
9. No step through Formal-800 accesses \(D_V\) or \(D_T\) tensor payloads.
   Reading the frozen project split manifest metadata is permitted and must
   be reported separately from payload access.
10. A later \(D_V\) evaluation requires its own frozen authorization and uses
    the relative performance contract above.  It is adaptive evidence because
    v21 already used \(D_V\); \(D_T\) remains reserved for confirmation.
